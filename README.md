# VK Education RAG

Проектная реализация RAG-системы для сбора веб-контента, его хранения, индексирования и семантического поиска по найденным фрагментам.

Текущая версия реализует базовый retrieval-контур: пользователь передаёт URL страницы, приложение извлекает текст, сохраняет документ и его фрагменты, строит эмбеддинги и добавляет их в векторную коллекцию ChromaDB. По текстовому запросу система возвращает наиболее близкие фрагменты.

> **Текущий статус:** реализованы загрузка веб-страницы по URL, чанкинг, хранение документов и фрагментов, векторная индексация и семантический поиск. Генерация итогового ответа с помощью LLM, endpoint `/ask` и пользовательский веб-интерфейс в предоставленной версии проекта отсутствуют.

## Архитектура

Приложение построено на FastAPI и разделено на API-слой, слой хранения данных и сервисы обработки.

### Контур добавления документа

1. `POST /ingest/` принимает URL.
2. `parser.py` загружает HTML-страницу и извлекает заголовок и основной текст.
3. `repository.py` сохраняет документ в SQLite.
4. `chunker.py` делит текст на фрагменты с перекрытием.
5. Фрагменты сохраняются в таблицу `chunks`.
6. `embedding.py` строит эмбеддинги с помощью `BAAI/bge-m3`.
7. `search_engine.py` записывает тексты, эмбеддинги и метаданные в коллекцию ChromaDB `rag_chunks`.

### Контур поиска

1. `POST /search/` принимает текстовый запрос и параметр `top_k`.
2. Для запроса генерируется эмбеддинг той же моделью `BAAI/bge-m3`.
3. ChromaDB выполняет поиск по косинусному расстоянию.
4. API возвращает найденные фрагменты, идентификаторы документа и фрагмента, индекс фрагмента и расстояние.

Поток данных:

```text
URL
  -> FastAPI /ingest/
  -> HTML parser
  -> Document (SQLite)
  -> Text chunking
  -> Chunk (SQLite)
  -> BAAI/bge-m3 embeddings
  -> ChromaDB

Search query
  -> FastAPI /search/
  -> BAAI/bge-m3 embedding
  -> ChromaDB similarity search
  -> Top-K chunks
```

### `app/api/`

HTTP-эндпоинты приложения. Здесь находятся обработчики запросов и связывание сервисов с API.

- `ingest.py`
  - `POST /ingest/` — принимает URL веб-страницы;
  - проверяет, не был ли URL добавлен ранее;
  - запускает парсинг, сохранение документа, чанкинг и индексацию;
  - возвращает ID, заголовок, URL, извлечённый текст и дату создания.
- `search.py`
  - `POST /search/` — принимает поисковый запрос;
  - вызывает семантический поиск;
  - возвращает найденные фрагменты.

### `app/database/`

Слой доступа к реляционной базе данных SQLite. Используется SQLAlchemy.

- `connection.py`
  - создаёт SQLAlchemy engine;
  - задаёт путь к `data/rag.db`;
  - создаёт фабрику сессий `SessionLocal`.
- `models.py`
  - `Document` — ORM-модель документа: заголовок, URL, полный текст и дата добавления;
  - `Chunk` — ORM-модель фрагмента: ссылка на документ, текст и порядковый индекс.
- `repository.py`
  - функции создания документов и фрагментов;
  - получение документа по ID или URL;
  - получение списка документов;
  - управление транзакциями при записи.

### `app/schemas/`

Pydantic-схемы для валидации входных данных и формирования ответов API.

- `search.py`
  - `SearchRequest` — поисковая строка и `top_k` (от 1 до 20, по умолчанию 5);
  - `SearchResult` — структура одного найденного фрагмента;
  - `SearchResponse` — ответ поиска с исходным запросом и списком результатов.

### `app/services/`

Бизнес-логика обработки и поиска документов.

- `parser.py`
  - загружает страницу по HTTP с помощью `httpx`;
  - разбирает HTML через BeautifulSoup и `lxml`;
  - определяет заголовок по `og:title`, `h1` или `title`;
  - удаляет служебные элементы (`script`, `style`, `nav`, `footer` и другие);
  - извлекает основной текст из `article`, `main` или `body`.
- `chunker.py`
  - разбивает текст на фрагменты по словам;
  - использует перекрытие соседних фрагментов;
  - проверяет корректность параметров разбиения.
- `embedding.py`
  - загружает SentenceTransformer-модель `BAAI/bge-m3`;
  - преобразует тексты в векторы;
  - нормализует эмбеддинги перед индексацией и поиском.
- `search_engine.py`
  - инициализирует постоянное хранилище ChromaDB в `data/chroma/`;
  - использует коллекцию `rag_chunks` с метрикой `cosine`;
  - индексирует фрагменты вместе с `document_id` и `chunk_index`;
  - выполняет поиск ближайших фрагментов по эмбеддингу запроса.

### `data/`

Локальные данные, создаваемые и используемые приложением.

- `rag.db` — SQLite-база с таблицами `documents` и `chunks`.
- `chroma/` — постоянное хранилище ChromaDB с коллекцией векторных представлений `rag_chunks`.

Каталог `data/` добавлен в `.gitignore`: база данных и индекс являются локальными runtime-артефактами и не должны попадать в Git при обычной разработке. В архиве проекта присутствуют примеры уже созданных файлов хранилищ.

### Корень проекта

- `main.py`
  - создаёт FastAPI-приложение;
  - создаёт таблицы SQLAlchemy при запуске;
  - подключает роутеры ingestion и search;
  - предоставляет `GET /health` для проверки состояния приложения.
- `requirements.txt` — файл зависимостей Python.
- `.gitignore` — исключает виртуальное окружение, Python cache и локальные данные.
- `README.md` — описание проекта, архитектуры и запуска.

## Модель данных

### `Document`

| Поле | Назначение |
|---|---|
| `id` | Первичный ключ документа |
| `title` | Заголовок страницы |
| `url` | URL источника, уникальный |
| `text` | Полный извлечённый текст страницы |
| `created_at` | Дата и время добавления |

### `Chunk`

| Поле | Назначение |
|---|---|
| `id` | Первичный ключ фрагмента |
| `document_id` | ID исходного документа |
| `text` | Текст фрагмента |
| `chunk_index` | Порядковый номер фрагмента в документе |

В ChromaDB для каждого фрагмента дополнительно хранятся его эмбеддинг и метаданные `document_id` и `chunk_index`. ID записи в коллекции соответствует строковому представлению `Chunk.id`.

## Параметры обработки текста и поиска

| Компонент | Текущая настройка |
|---|---|
| Размер чанка | 150 слов |
| Перекрытие | 20 слов |
| Минимальный размер чанка | 15 слов |
| Модель эмбеддингов | `BAAI/bge-m3` |
| Размер batch при кодировании | 8 |
| Нормализация эмбеддингов | Включена |
| Векторное хранилище | ChromaDB |
| Метрика расстояния | Cosine |
| `top_k` по умолчанию | 5 |
| Допустимый `top_k` | От 1 до 20 |

## API

После запуска документация FastAPI доступна по адресу `http://127.0.0.1:8000/docs`.

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка доступности приложения |
| `POST` | `/ingest/` | Загрузка и индексация веб-страницы по URL |
| `POST` | `/search/` | Семантический поиск по индексированным фрагментам |

### Добавление документа

`POST /ingest/`

Тело запроса:

```json
{
  "url": "https://example.com/article"
}
```

Обработчик возвращает сведения о сохранённом документе. Если URL уже существует, возвращается HTTP `409`. Ошибки валидации URL и загрузки страницы обрабатываются отдельно.

### Семантический поиск

`POST /search/`

Тело запроса:

```json
{
  "query": "Как работает семантический поиск?",
  "top_k": 5
}
```

Ответ содержит исходный запрос и массив результатов. Каждый результат включает `chunk_id`, `document_id`, `chunk_index`, текст фрагмента и `distance` — расстояние, возвращённое ChromaDB (для используемой метрики cosine меньшее значение означает большую близость).

## Быстрый старт

### 1. Создание виртуального окружения

```bash
python -m venv venv
```

Windows:

```powershell
.\venv\Scripts\activate
```

Linux / macOS:

```bash
source venv/bin/activate
```

### 2. Установка зависимостей

Код проекта использует FastAPI, Uvicorn, SQLAlchemy, HTTPX, BeautifulSoup, lxml, ChromaDB и Sentence Transformers. В текущем `requirements.txt` из архива перечислены не все используемые пакеты, поэтому для запуска установите зависимости явно:

```bash
python -m pip install fastapi uvicorn sqlalchemy httpx beautifulsoup4 lxml chromadb sentence-transformers
```

### 3. Запуск приложения

Из корневой директории проекта:

```bash
uvicorn main:app --reload
```

При первом запуске `SentenceTransformer` загрузит модель `BAAI/bge-m3`. Для этого требуется доступ к источнику размещения модели и достаточно места на диске.

### 4. Проверка работы

- Health check: `http://127.0.0.1:8000/health`
- Swagger UI: `http://127.0.0.1:8000/docs`

Сначала отправьте URL через `POST /ingest/`, затем выполните запрос через `POST /search/`.

## Ограничения текущей версии

- Добавление контента реализовано для веб-страниц, переданных по URL; загрузка локальных PDF-файлов и других форматов в представленных исходниках не реализована.
- Поиск возвращает релевантные фрагменты, но не генерирует связный ответ с помощью LLM.
- В API нет endpoint `/ask`.
- В архиве исходников нет frontend-интерфейса.
- Парсер использует эвристический выбор основного HTML-блока (`article`, `main`, `body`), поэтому качество извлечения зависит от структуры конкретного сайта.
- SQLite и локальное хранилище ChromaDB рассчитаны на локальный прототип; отдельная production-конфигурация и миграции схемы в текущей версии не представлены.
